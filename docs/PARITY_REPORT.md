## Extra checks the QA pass asked for

- **390 px layout:** the landing, pricing, plan, docs, changelog, login and signup pages, plus 11 app routes and the issue pane, have no horizontal scroll (`scripts/qa-shots.mjs`; `after-m-*.jpg`). Fixed along the way: the app sidebar widened the page at 390 (the grid track had no `minmax(0, …)`), the 390 pricing layout carried the original's dead footer and a fake menu button, and the 390 fig cards overlapped.
- **Console:** `scripts/e2e-hygiene.mjs` loads every site page and every app route as the demo account and as a guest, and fails on any console error, `<a>` without an href, upgrade/plan/"coming soon" copy, or the bare original name. All eight e2e scripts pass against `next dev` and against a production build (`next start`, `DEMO_MODE=1`). The live login page also loads with zero console errors and no third-party scripts (no Turnstile).
- **Password-reset email delivery and Google sign-in on the clone:** not testable locally, because this checkout has no Firebase env. Production and preview have it. *Unverified* in this sprint.
- **Passkey and invalid-email behaviour on the original:** needs a Linear session or Linear's client app (its login is client-rendered), so these stay *unverified*. Our empty-email copy matches the QA's observation.

## Needs a human decision

1. **Guest workspace (#4):** kept on purpose (IsDead rule). Set `GUESTS=0` if Linear parity should win and `/app` should bounce to login.
2. **PostHog (#4, from another session):** it follows the hub's `yourappisdead/ANALYTICS.md` contract (`product` / `surface=landing|app` / `platform`), not the older miroisdead contract (`app` / `app_family` / `surface=site|app` / `base_path`). Also, `NEXT_PUBLIC_POSTHOG_KEY` is **not set** on the linearisdead Vercel project, and adding it was blocked by the permission classifier, so the owner needs to add it for Production and Preview. #4 is based on `main` and touches `Workspace.tsx` / `AuthScreen.tsx`, so expect a rebase onto this stack, and its issue events will need re-wiring to the new pages.
3. **Shared workspaces:** workspaces live in each browser (localStorage), and Import / export moves them. Real multi-user teams (shared issues, invites) need a Firestore-backed store via `lib/store`, which is free on the current plan but is a larger change.
4. **Naming in pricing (#16) and the hero (#17):** the original's brand-prefixed feature names are left unbranded rather than renamed to "LinearIsDead Agent", because that would claim features this app doesn't have.
