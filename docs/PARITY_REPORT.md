# Parity report: LinearIsDead vs Linear (QA pass of 2026-10-16)

18 findings from the hands-on QA pass (7 high, 5 medium, 6 low). Each one is either **Fixed** or a **Justified exception**. Screenshots are in `docs/qa/2026-10-16/`: `before-*` shows the base branch (`fix/brand-mark`) and `after-*` shows this stack. Each area has a Playwright script in `scripts/e2e-*.mjs`, which drives real mouse and keyboard events and fails on any console error. `scripts/qa-shots.mjs` takes the screenshots and runs the 390 px horizontal-scroll check.

**How the [gk] rows were checked.** No Linear account was created: the IsDead rule is never to create accounts or enter passwords on the original. Linear's in-app behaviour was read from its public docs on 2026-10-16. The table below cites the pages used. Rows the docs did not settle are marked *unverified*.

| # | Finding | Status | PR | How it was closed |

| 4 | Sign out lands on marketing; `/app` opens a guest workspace | Fixed + **justified exception** | auth | Sign out now lands on `/login`, as on Linear. Opening `/app` signed out still starts a guest workspace by design (IsDead rule: "no login unless needed"). The guest sidebar says "Guest · Sign in to keep your work", and work done as a guest moves into the account on first sign-in. `GUESTS=0` turns guests off if Linear parity should win. Sign-out behaviour is not written down in Linear's docs (*unverified*; [login-methods](https://linear.app/docs/login-methods) only covers signing out everywhere). |
| 8 | No SAML SSO or passkey buttons | **Justified exception** | auth | IsDead auth rule: Google and email + password only, through the shared yourappisdead Firebase. SAML (Enterprise-only on Linear) and passkeys are not offered, and no greyed-out buttons are shown. |
| 9 | Login copy and links | Fixed | auth | "Don't have an account? **Sign up** or **learn more**" is now two links: `/signup` (its own URL, no in-place toggle) and the homepage. "Forgot password?" stays but moves to the password step: Linear signs in with magic links, while IsDead uses passwords, and reset emails are allowed. |
| 10 | No inline empty/invalid email error, no Back to login | Fixed | auth | The email step is "What's your email address?".
